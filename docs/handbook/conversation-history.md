# Search and conversation history

Open **Search chats** in the sidebar, or press **⌘K / Ctrl+K**. An empty search shows recent saved chats across your projects. Typing searches titles and saved user/assistant message text. Word beginnings match: `quarter reven` can find “quarterly revenue”. All search words must occur in one title or one message, including separate final-text blocks within that message. Results use recent activity order; they are not ranked by semantic relevance. Punctuation is ignored by the PostgreSQL text parser, and words are not translated or stemmed.

Each result shows its project and date. **Include archived chats and projects** expands the results to your own archives; it does not grant access to another account’s conversations. Temporary chats, memories, hidden reasoning, tool inputs/results, model-identity metadata and attachment contents are not searched. Saved voice transcripts are searchable when they are stored as ordinary user or assistant text. Search makes no model or external service request.

Use **↓** from the input to reach results, **↑** on the first result to return to the input, **Enter** to open a result and **Esc** to close. Tab remains available for every control. The dialog scrolls within the viewport on mobile and returns focus to its opener, or to the navigation toggle when the mobile sidebar has closed. Changing the query hides the previous results immediately and cancels the obsolete request. Closing the dialog cancels its pending request too.

The sidebar and each project’s conversation list load 30 chats at a time, with pinned chats first. **Load more chats** retrieves the next page. Search loads 20 results per page. A failed later page preserves the already loaded rows and offers a retry. New activity, pinning and moves can change a chat’s position; refresh begins from the current ordering. Pages are not a frozen database snapshot, and the client removes duplicate IDs if a chat moves between requests.

## Coverage and privacy boundaries

Migration 0012 indexes at most the first **65,536 Unicode text characters among the first 512 content blocks of each saved message**, plus the first 512 characters of its title. This bound protects migration and future writes from unusually large legacy imports. Content beyond that prefix remains in the conversation but will not match search. PostgreSQL also omits individual words of 2 KiB or longer from its text index. Only exact text blocks containing a string qualify; malformed legacy shapes are ignored. Separate text blocks receive a word boundary. Search operates on saved text, including Markdown/code source, rather than executing or rendering it. Snippets are capped at 280 characters and displayed as escaped text, with no active HTML or model-supplied links.

Every request refreshes the current account, filters conversations by owner, and checks project ownership. Administrators do not receive a global conversation search. Disabled or deleted accounts cannot continue with an old session cookie. Search and history responses use `Cache-Control: private, no-store`. Route handlers do not log search text or SQL parameters, and error responses contain neither. Reverse proxies can log GET query strings; configure access-log redaction if search-term retention matters to your deployment. As with other saved data, database backups can contain searchable text; this feature is not a retention or erasure guarantee.

## API and operator details

`GET /api/conversations` retains the existing `conversations` array and conversation fields, and adds `nextCursor` and `hasMore`. The default page size is 30. Its existing scope stays the same: unfiled conversations by default, or an owned `projectId`; `includeArchived=true` includes archived conversations. An explicitly requested owned archived project remains available through this existing list API.

`GET /api/conversations/search?q=quarter+reven` searches all owned projects and unfiled chats, or an optional owned `projectId`. Its default page size is 20. Archived conversations and archived projects are excluded unless `includeArchived=true`. Results add a bounded `snippet`, `matchedField`, `projectName` and `projectArchived`. An empty query returns recent saved chats.

Both routes accept `limit` from 1 to 100 and an opaque `cursor` from the preceding page. Search input is limited to 200 characters; duplicate parameters, invalid filters and invalid cursors are rejected. Cursors are signed with the installation’s authentication secret and bound to the account, endpoint, query and filters. Changing those filters requires a fresh first page. Rotating the authentication secret invalidates existing cursors. The cursor carries PostgreSQL’s full microsecond timestamp and a UUID tie-breaker; it never round-trips through a JavaScript `Date`. Existing response timestamps remain ISO strings at millisecond precision.

Run `pnpm db:init` as usual before starting the upgraded app. Migration 0012 follows the unchanged task-origin migration 0011 and adds one immutable extraction function and three indexes, without rewriting conversation/message rows. Index creation may take time and hold write locks on a large installation; apply it in a maintenance window and retain the normal tested backup. The function is managed by the migration, so schema push is not a replacement for initialization. PostgreSQL 16 or later is supported. GIN is PostgreSQL’s preferred full-text index type; the bounded extraction also stays below its vector-size limits. [PostgreSQL index guidance](https://www.postgresql.org/docs/16/textsearch-indexes.html), [text-search limits](https://www.postgresql.org/docs/16/textsearch-limitations.html).

Database reads have a two-second statement timeout and a short lock timeout. Client aborts cancel the specific running PostgreSQL query without closing the shared pool. Timeouts return a generic retry message. The prefix search uses PostgreSQL’s `simple` configuration; it is lexical search, with no embeddings or language-specific relevance model. [PostgreSQL query and headline behavior](https://www.postgresql.org/docs/16/textsearch-controls.html).

## Validation

`POLARIS_HISTORY_INTEGRATION=1 pnpm test:integration:history` requires a loopback PostgreSQL test cluster with permission to create a uniquely named disposable database and a completed production build. It uses synthetic users and text, relocates the standalone output, and removes its server/database/files afterwards. It verifies retained data through 0010 → 0011 → 0012, repeat initialization, malformed/large legacy messages, matches across text blocks, sub-millisecond cursor ties, project/archive ownership, disabled/deleted sessions, bounded inputs, cursor binding, and real SQL/HTTP cancellation. Set `REQUIRE_POSTGRES_16=true` for the CI version gate. No provider credentials or calls are used.

The unit suite covers cursor integrity and scope, bounded inputs/snippets, page deduplication and cancellation before/after a query starts. Browser acceptance covers desktop/mobile dialog layout, focus restoration, keyboard navigation, query changes, archive filtering, pagination and owner-scoped reload.

Opening a saved result also validates its display parts. Malformed legacy roots or non-string text are ignored, file links use the owned file endpoint, and unknown metadata is never converted into message text. Valid recorded model identity, thinking, tool displays and file cards remain available. This read-time normalization does not rewrite stored or provider continuation history.
